# pi-qq — features-v2.md

> V2 增量：F8 语音自动转写、F9 轻量日志基础设施、F10 文件消息等待指令、F11 文件存储与去重。
> 基线见 [features-v1.md](./features-v1.md)；本文只描述新增/变更内容。

## 1. 背景与结论

- 当前语音附件被当作普通文件保存，pi 只能本地解码 SILK 并转写；慢且可能误识别。
- 实测确认 C2C 语音消息的 `attachments[]` 包含 `asr_refer_text`（示例：`"测试。"`），`content` 为空；SDK 1.0.5 已透传该字段。
- 结论：直接使用 QQ 内置 ASR；不下载语音附件，不接本地或外部 STT。

## 2. F8 语音消息自动转写

### 触发与识别

- 仅 C2C、白名单用户。
- `content_type === "voice"` 视为语音消息。
- 读取并 trim `asr_refer_text`。

### 行为

| 情况        | 处理                                                                                  |
| ----------- | ------------------------------------------------------------------------------------- |
| 有 ASR 文本 | `markQQTrigger()` → `pi.sendUserMessage(text, { deliverAs })`                         |
| ASR 为空    | 回复 `Could not transcribe this voice message; please resend or type it.`，不触发 run |
| 语音消息    | 不下载 `url` / `voice_wav_url`，不保存文件，不走图片/文件分支                         |

- 语音和文字是两条独立消息，不做同条组合。
- 转写文本不参与 QQ 命令解析，作为普通用户消息交给 pi。
- 正常一条语音消息只有一个语音附件；多值时按顺序换行拼接，仅作防御。

### 不实现

- 本地 Whisper 或外部 STT 回退
- 保存原始语音

### 代码边界

- 新增 `src/voice.ts`：`isVoiceAttachment()`、`resolveVoiceTranscript()`。
- `src/inbound.ts`：在图片/文件分流前增加语音分支，处理完直接返回。

### 验收

- 发语音后 pi 直接收到文本，不出现 `.amr` / `.silk` 路径。
- 无 `ffmpeg`、`pilk`、`faster-whisper` 等调用，工作区不新增语音文件。
- 空 ASR 只回提示，不启动 agent。
- 文字、图片、文件行为不变。

## 3. F9 日志基础设施

### 实现

- 自研轻量 logger，不引入第三方框架。
- 单文件按天：`<cwd>/.pi/pi-qq/logs/pi-qq-YYYY-MM-DD.log`；可用 `PI_QQ_LOG_DIR` 覆盖。
- 每条一行 JSON：`time`、`level`、`scope`、`msg` + 结构化字段。
- 日志写入失败不得影响 QQ 消息处理。
- SDK 日志接入同一 logger。

### 配置

```json
{
  "logLevel": "silent"
}
```

| 级别     | 输出                                                 |
| -------- | ---------------------------------------------------- |
| `silent` | 不写日志（默认）                                     |
| `error`  | error                                                |
| `warn`   | warn + error                                         |
| `info`   | info + warn + error                                  |
| `debug`  | 全部，含 raw 事件、附件、prompt、工具参数/结果、正文 |

- 配置键使用 `logLevel`，不使用 `log_level`。
- 移除 `debug` 配置；旧 `debug: true` 迁移为 `logLevel: "debug"`，其他情况默认 `silent`。
- 移除 `debug` 控制的 QQ 气泡时间戳；日志级别不影响聊天展示。
- `info` 只记元数据（如 `hasAsr`、`asrLength`）；`debug` 才记录 `asr_refer_text` 全文和完整附件。

### 验收

- 各级别过滤正确；默认 `silent` 不产生日志。
- `logLevel: "debug"` 能看到语音原始附件和 ASR 文本；`info` 看不到正文。
- 旧 `debug` 配置可迁移。
- 日志路径、日期滚动、写入失败降级正常。

## 4. F10 文件消息等待指令

### 目标

QQ 不能同时发送文字和文件。非图片文件上传后先保存，等待用户下一条文字或语音指令，避免立即触发 pi。

### 行为

| 情况         | 处理                                                                                                          |
| ------------ | ------------------------------------------------------------------------------------------------------------- |
| 只发文件     | 保存到 F11 定义的 session uploads 目录；加入 pending 队列；不回复；不调用 `sendUserMessage` / `markQQTrigger` |
| 连续上传文件 | 追加到同一 pending 队列；不回复                                                                               |
| 下一条文字   | 合并 pending 文件与当前文件，`formatFilePrompt(files, text)` 后 `sendUserMessage`；清空 pending；触发 run     |
| 下一条语音   | 用 ASR 文本作为指令，合并 pending 文件；清空 pending                                                          |
| `/new`       | 清空 pending                                                                                                  |
| 其他 QQ 命令 | 不消费 pending，命令行为不变                                                                                  |
| 图片         | 保持 v1 行为；图片可以随文字发送，不进入 pending                                                              |

- 部分文件保存失败：只把成功文件加入 pending，并回复失败清单。
- 文件消息不回复确认，不触发 agent run。
- pending 状态只保存在当前会话内存；pi 重启后丢失，已落盘文件仍保留。
- pending 文件按保存顺序合并；消费后清空，不重复注入。

### 代码边界

- `src/inbound.ts`：维护 pending 队列；文件消息先入队，下一条文字/语音指令出队并合并。
- `/new` 命令清空 pending。
- 图片路径不变。

### 验收

- 只发文件：文件已保存，不回复，`sendUserMessage` / `markQQTrigger` 均未调用。
- 文件后发文字：只触发一次 run，提示词包含文件路径和文字指令。
- 连续两个文件后发文字：两个文件路径都在提示词中。
- 文件后发语音：ASR 文本与文件一起注入。
- `/new`：pending 被清空。
- 文件保存失败：不进入 pending，仍回复失败信息。
- 图片、普通文字、既有文件+文字行为不变。

## 5. F11 文件存储与去重

### 路径

- 非图片文件保存到：
  ```text
  <cwd>/.pi/pi-qq/<sessionId>/uploads/
  ```
- `sessionId` 来自 `ctx.sessionManager.getSessionId()`。
- 不再使用日期目录或 `msgId` 子目录。
- 文件名使用清理后的 basename；同名文件通过后缀区分。

### 索引

索引文件：

```text
<cwd>/.pi/pi-qq/<sessionId>/uploads/.index.json
```

格式只记录文件名和内容摘要，不记录完整路径：

```json
{
  "a.txt": "<sha256>",
  "a-1.txt": "<sha256>"
}
```

### 保存规则

| 情况                 | 处理                                                         |
| -------------------- | ------------------------------------------------------------ |
| 文件名不重复         | 保存文件；计算 SHA-256；写入索引；引用文件                   |
| 文件名重复，内容不同 | 保存为下一个可用文件名（如 `a-1.txt`）；写入索引；引用新文件 |
| 文件名重复，内容相同 | 不保存新文件；复用已有文件路径                               |

- 只有文件名重复时才比较内容摘要；文件名不重复时即使内容已存在于其他文件名下，也按规则保存新文件。
- 文件名重复且内容不同时，从 `name-1.ext` 开始寻找可用文件名；如果该后缀文件已存在且内容相同，复用该后缀文件。
- 文件名重复且内容相同，复用已有同名文件，不生成副本。
- 图片、语音不进入该文件索引。

### 索引维护

- QQ 登录 / 会话启动时加载索引：
  - 对每个 `fileName` 检查 `uploads/fileName` 是否存在。
  - 文件不存在则删除对应索引项。
  - 只做存在性检查，不读取文件内容，不重新计算 hash。
  - 索引有变化才原子写回。
- 保存或复用文件前再次检查目标文件是否存在；不存在则删除索引项并按新文件处理。
- 索引缺失或损坏时从空索引开始；遇到同名文件时再计算已有文件 hash 并补写索引。
- 文件保存与索引更新按用户消息串行执行；当前消息处理完成前不处理下一条，避免并发覆盖索引。
- 索引写入失败只记 warn，不影响文件保存和消息处理。
- 不新增配置参数。

### 与 pending 的关系

- 同名同内容重复上传：只返回一个 `SavedFile`，pending 不重复加入。
- 不同文件名但内容相同：按规则保存两份，pending 保留两个路径。

### 验收

- 文件保存到 `.pi/pi-qq/<sessionId>/uploads/`，不再出现日期 / `msgId` 目录。
- 索引文件只包含文件名到 SHA-256 的映射。
- 文件名不重复：保存并引用。
- 同名不同内容：保存为 `name-1.ext` 并引用新文件。
- 同名同内容：不新增文件，复用已有路径。
- 登录 / 会话启动：删除指向不存在文件的索引项，且不重新计算所有文件 hash。
- 索引缺失或损坏：同名文件仍能通过现有文件 hash 正确判断。
- 索引写入失败不影响文件保存和消息处理。

## 6. 配置变更

| 配置       | 变更                 |
| ---------- | -------------------- |
| `logLevel` | 新增；默认 `silent`  |
| `debug`    | 移除；仅保留迁移读取 |

## 7. 限制

- `asr_refer_text` 可能为空或识别不准确；V2 只提示用户重发或改用文字，不做回退。
- `debug` 日志可能包含消息正文和 URL token，仅在排查时本地开启。
- 文件 pending 不跨 pi 重启；未消费的文件仍保留在 `.pi/pi-qq/<sessionId>/uploads/` 下。
- 索引信任写入时的 hash；如果用户手动修改同名文件内容，登录时的存在性检查不会发现。
